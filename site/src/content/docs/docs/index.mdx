PAL is the self-hosted runtime for AI agents. The agent loop runs on your control plane; untrusted code runs in its own microVM. Durable runs, hard budgets, capability-routed models and signed receipts come with it.

The control plane owns the agent: workflow interpreter, journal, model router and budgets. When a durable `tool_call` step runs code, the workflow engine calls `ExecTool` on the runtime-manager on a data-plane host, which runs the code inside a microVM whose PID 1 is the harness. In broker mode (`LANTERN_EGRESS_MODE=broker`, opt-in, Firecracker only) the VM has no network device; its requests leave over vsock through a host broker that checks the allowlist and adds the credential.

<Diagram name="your-cloud" />

The data-plane agent dials out to the control plane, so your VPC opens no inbound ports. Untrusted code and its data run in your cluster; self-host the control plane too and prompts, keys and run data never leave your infrastructure.

## What the runtime gives you

- **Durable execution.** A crash mid-step resumes from the journal. Completed steps are skipped and idempotency keys stop double side effects. See [Durable execution](/pal/docs/runtime/durable-execution/).
- **Isolation classes.** runc, gVisor, Kata and Firecracker by declared class. Untrusted code is refused rather than downgraded when the hardened runtime is missing. See [Isolation](/pal/docs/runtime/isolation/).
- **Token streaming.** Session replies stream token by token over SSE, with no buffering between provider and client. Tool-using turns return one completed message. See [Streaming](/pal/docs/runtime/streaming/).
- **Observability.** Control-plane HTTP/gRPC and step spans carry `tenant_id`, `run_id` and `step_id`; the trace context propagates into the in-VM harness. See [Observability](/pal/docs/runtime/observability/).
- **Budgets.** Hard caps on cost, tokens and runs per day, per agent and tenant-wide; over the cap, the call returns HTTP 402 before the model is called. Workflow runs also stop mid-run at the per-run cap, and tool nodes respect per-tool limits. See [Budgets](/pal/docs/build/budgets/).
- **Evaluations.** Pin a baseline per branch and fail CI on regression with HTTP 422. Replay past failures before promoting a version. See [Evaluations](/pal/docs/build/evaluations/).
