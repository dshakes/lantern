The full history is in [CHANGELOG.md](repo:/blob/master/CHANGELOG.md).

## Breaking

- **Firecracker guests no longer get caller env on the kernel cmdline.** `spawn.json` is the only channel for caller env; the cmdline carries just the manager-owned `LANTERN_ENV`, `LANTERN_MANAGER_ADDR` and `LANTERN_WORKLOAD_UID`. Harness builds that predate `spawn.json` are unsupported for caller env. The old path leaked values such as an instance token into console logs.

## Renamed

The product is now **PAL** ([ADR 0032](repo:/blob/master/docs/adr/0032-rename-lantern-to-pal.md)). Docs, dashboard copy, widget and CLI help say PAL, the CLI binary is `pal`, and variables are spelled `PAL_*`. The old `LANTERN_*` names are still read as aliases, and wire identifiers (`x-lantern-service-token`, `lantern.secret/`, `lantern.v1`) are unchanged.

## New since 0.2.0

- **[Demo mode](/docs/start/demo/).** `make demo` or `pal demo`: Docker only, no API key. Each visitor gets a private workspace with recorded answers, deleted after 30 minutes.
- **[Knowledge base and handoff](/docs/pal/knowledge/).** Upload docs for cited answers, and hand a chat to a human with a Slack ping.
- **[Webhook triggers](/docs/build/triggers/).** A signed public URL per agent. GitHub, Sentry, PagerDuty or any HMAC sender starts a run; duplicates are deduplicated.
- **[Accounts and sign-up](/docs/build/accounts/).** Gated sign-up, email verification, password reset, invite codes, captcha, data export and workspace deletion.
- **[Budgets, enforced](/docs/build/budgets/#what-is-enforced-where).** Tokens per day, per-run caps inside workflows, per-tool limits, and fail-closed 503 when a hard-fail budget cannot be read.
- **[Capability names](/docs/build/models/#capability-names).** Every capability and optimize target, and the model it resolves to per provider.
- **[Connector actions](/docs/build/connectors/#newer-actions).** Slack thread replies, GitHub PR comments, Sentry issues, Calendar events, PagerDuty, and a recorded test mode.
- **[Egress DLP](/docs/architecture/security-boundaries/).** A per-tenant policy the egress broker applies to TLS-terminated and plain-HTTP egress: card numbers, secret-key prefixes, email and phone thresholds. A guard rail and audit trail, not the boundary.
- **Host-asserted measurement (ADR 0031).** Every Firecracker cold spawn records a SHA-256 over kernel, rootfs, harness, cmdline and spawn contract; signed receipts carry it as `softwareMeasurement`. It proves what the host launched, not what ran inside; hardware attestation is not done.
- **Secure by default (ADR 0042).** API-key scope enforcement is on in production and every authenticated GET route now carries a scope; `PAL_AUTHZ_ENFORCE=0` opts out with a warning. Row-level security is on in production when `PAL_APP_DB_PASSWORD` is set, and startup is fatal without it unless `PAL_RLS_ENFORCE=0`.
- **Mutual TLS on internal gRPC (ADR 0043).** Every internal gRPC server now requires a client certificate (`PAL_GRPC_TLS_CA`/`_CERT`/`_KEY`, optional SPIFFE allowlist) in addition to the service token, and production refuses to start without it unless `PAL_GRPC_INSECURE=1`. The customer-VPC data-plane tunnel is the exception: server-auth TLS with a bootstrap token and session JWT.
- **Multi-region, active-passive (ADR 0046).** `PAL_REGION`, `PAL_READ_ONLY` and `PAL_FENCE_EPOCH` fence a standby region; data-plane agents fail over across `PAL_CONTROL_PLANE_ENDPOINTS` in order and fail back on `PAL_CONTROL_PLANE_FAILBACK_INTERVAL`. See the `region-failover` runbook in the repo.
- **[Examples](/docs/start/examples/) and test lanes.** Daily digest, Telegram assistant, voice receptionist and data analyst, each with a fixture path that needs no provider key; Playwright dashboard specs; a CI lane that runs them on every PR.
- **Telegram and WhatsApp replies.** The surface gateway now posts the run's output back to the chat; before, the answer was dropped.
- **[Disk snapshots](/docs/runtime/sandbox-lifecycle/#snapshots).** Snapshots capture the VM disk; restore and fork stage from it.
- **[Real microVMs on a Mac](/docs/runtime/local-microvms/).** `make lima-up`, then `make lima-e2e`: Firecracker on KVM inside a Lima guest, on Apple Silicon M3+.
- **[End-to-end tests](/docs/build/testing/).** `make test-e2e` against a live stack, with a spend policy and `make e2e-clean`.

## Fixed

- **Receipt verification detects an edited payload.** `POST /v1/runs/receipts/verify` used to compare only the signature string.
- **Fork and restore clone the VM disk copy-on-write** (`FICLONE`) on XFS and btrfs instead of byte-copying it.
- Workflow `connector` nodes can call Sentry and PagerDuty; a workflow whose JSON held a backslash no longer silently runs as a plain LLM call; the resumed node after an approval park is journaled.
