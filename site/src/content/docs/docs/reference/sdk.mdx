Three SDKs: TypeScript (`@pal/sdk`), Python (`pal-sdk`, imported as `pal`) and Go (`github.com/dshakes/pal/packages/sdk-go`). They cover agents, runs, sessions, connectors, budgets, evals, experiments, marketplace, MCP, receipts, feedback, rehearsals and sandbox VMs. The TypeScript client has the most surface; the listings below show what each one exposes.

The SDKs wrap the REST API in typed methods, so you call `client.runs.create(...)` instead of writing HTTP. Use them to trigger agents from your app, wire runs into your backend, or script bulk operations. For the raw endpoints see the [API reference](/docs/reference/api/).

## TypeScript SDK

### Installation

<Aside type="caution" title="Registry packages are not published yet">
`@pal/sdk` is not on npm, so `npm install @pal/sdk` fails. Install from a checkout.
</Aside>

```bash
# in your checkout of github.com/dshakes/pal
( cd packages/sdk-ts && npm install && npm run build )
# in your project: a file path, not the registry
npm install /path/to/pal/packages/sdk-ts
```

After that, `import { PalClient } from "@pal/sdk"` resolves to the built `dist/`. Rebuild after pulling changes.

### Client setup

```ts
import { PalClient } from "@pal/sdk";

const client = new PalClient({
  apiKey: process.env.PAL_API_KEY,   // hlx_live_...
  baseUrl: process.env.PAL_API_URL,  // e.g. http://localhost:8080
});
```

With no constructor options the SDK reads `PAL_API_KEY` and `PAL_API_URL`. If `PAL_API_URL` is unset, the base URL defaults to `https://api.pal.run`, so set it for a self-hosted control plane. (`PAL_RUNTIME=true` is a different switch: the platform sets it inside a running agent to enable the production sidecar.)

### Creating and streaming a run

```ts
import type { Run } from "@pal/sdk";

// Create a run (create() returns an event stream instead when you pass stream: true)
const run = (await client.runs.create({
  agent: "research-agent",
  input: { topic: "quantum computing" },
})) as Run;

console.log(run.id, run.status); // queued

// Stream events for the run
for await (const event of client.runs.events(run.id)) {
  console.log(event.kind, event.stepId, event.data);
  // kinds include step_started, step_completed, step_failed, tool_call, tool_result, llm_delta, log, approval, end
}

// Fetch final result
const finished = await client.runs.get(run.id);
console.log(finished.status, finished.output);
```

### Interactive sessions

```ts
// Create a session
const session = await client.sessions.create({ agent: "my-agent" });

// Stream a message turn
for await (const chunk of client.sessions.streamMessage(session.id, {
  content: "What is the capital of France?",
})) {
  // chunk.type is "delta" | "completed"; a server-side message_error throws MessageStreamError
  if (chunk.type === "delta") process.stdout.write(chunk.delta);
  if (chunk.type === "completed") console.log("\nDone:", chunk.usage);
}

// Non-streaming send: returns immediately; the reply arrives on sessions.events()
await client.sessions.sendMessage(session.id, {
  content: "Follow-up question",
});

// Cleanup
await client.sessions.delete(session.id);
```

### Error handling

```ts
import { PalApiError, MessageStreamError } from "@pal/sdk";

try {
  await client.runs.create({ agent: "my-agent", input: {} });
} catch (err) {
  if (err instanceof PalApiError) {
    console.error(err.status, err.message);
  }
}

// Errors during a session stream
try {
  for await (const chunk of client.sessions.streamMessage(id, { content: "hi" })) {
    // ...
  }
} catch (err) {
  if (err instanceof MessageStreamError) {
    console.error("stream error:", err.message);
  }
}
```

Retries are built in. The TypeScript client retries HTTP 429, 503 and network errors up to 3 attempts with full-jitter backoff (500 ms base, 4 s cap). It never retries other 4xx or 5xx. There is no separate `@pal/retry` package.

Sandbox VMs live under `client.runtime` in TypeScript and Python; Go has `ScheduleVM`, `PauseVM`, `ResumeVM`, `ForkVM`, `ListFiles`, `ReadFile` and `WriteFile`. See [Sandbox lifecycle](/docs/runtime/sandbox-lifecycle/).

## Python SDK

<Aside type="caution" title="Status">
The Python management client is usable today. The in-agent runtime context (`ctx.llm`, `ctx.tools`, `ctx.mem` and the rest) raises `NotImplementedError`; write agent logic in TypeScript for now. Install from the repo: the `pal-sdk` name on PyPI belongs to an unrelated project, so `pip install pal-sdk` installs the wrong package.
</Aside>

### Installation

```bash
# from the root of your checkout
pip install ./packages/sdk-python
# optional: LangChain deepagents sandbox backend (pal.integrations.deepagents_sandbox)
pip install "./packages/sdk-python[deepagents]"
```

### Client setup

```python
from pal import PalClient

client = PalClient(
    api_key="hlx_live_your_key",        # or PAL_API_KEY env var
    base_url="http://localhost:8080",   # or PAL_API_URL env var
)
# Request methods are coroutines: call from async code, or asyncio.run(main())
```

`PalClient` is built on `httpx.AsyncClient`: every request method is `async def`; `runs.events`, `sessions.stream_events` and `runtime.exec_stream` return async iterators (`async for`). Use `async with PalClient(...) as client` or call `await client.close()`.

run = await client.runs.create(agent="research-agent", input={"topic": "AI safety"})

## Agent runtime (TypeScript)

Inside an agent bundle, `ctx` gives you durable steps, LLM calls, tools, memory and connectors. Each step is journaled, so a crashed run resumes instead of restarting:

```ts
import { agent, step } from "@pal/sdk";

export default agent<{ query: string }>({
  name: "my-agent",
  model: "auto",
  async run({ input, ctx }) {
    // Durable step — journaled, idempotent, resumable on crash
    const data = await step("fetch-data", async () => {
      return ctx.tools.web.search(input.query);
    });

    // LLM call — addressed by capability; the model router picks the vendor model
    const summary = await step("summarize", async () => {
      return ctx.llm.complete({
        messages: [{ role: "user", content: `Summarize: ${data}` }],
        capability: "reasoning-small",
      });
    });

    return { summary };
  },
});
```

Use capability names like `auto`, `reasoning-large`, `chat-small`, `vision-large`. Do not hardcode a vendor model. The model router maps the capability to a concrete model at call time. See [Models](/docs/build/models/) for the full list.

### Parallel fan-out

```ts
const results = await step.map("search", queries, async (query) => {
  return ctx.tools.web.search(query);
});
```

### Human approval

```ts
// Blocks until a human grants or denies.
await ctx.approval.request({
  reason: "Send this email to 500 users?",
  expiresAt: "2026-12-01T00:00:00Z",
});
// Reaching this line means it was granted. Denial or timeout throws PalError.
```
