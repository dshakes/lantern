Every environment variable the control plane, schedulers, runtime manager, in-VM harness and dashboard read, with its default, what it does and the line of code that reads it. **Required in prod** means the process refuses to start (or, for the harness, refuses to run the workload) when `PAL_ENV` is `prod`, `production` or `staging` and the value is missing. Flag values accept `1`, `true` or `on` unless a row says otherwise.

**Naming.** Every variable is spelled `PAL_*`. The old `LANTERN_*` spelling is still read as a legacy alias, so existing deployments keep working; when both are set, `PAL_*` wins.

## How to use this page

Local development needs none of these: `make run-api` sets the database, Redis and S3 values, and every security variable has a dev default or is skipped with a warning. For production, start from the [checklist below](#production-checklist), then see [Operations](/docs/operate/operations/) for how the Helm chart supplies them. A production process that is missing a required value logs it by name and exits at startup.

## Production checklist

| Service | Must be set |
| --- | --- |
| Control plane | `JWT_SECRET`, `PAL_RECEIPT_SECRET`, `PAL_CREDENTIAL_KEY`, `PAL_GRPC_SERVICE_TOKEN`, `PAL_APP_DB_PASSWORD` (turns on row-level security; missing it is fatal unless `PAL_RLS_ENFORCE=0`), `PAL_CONTROL_PLANE_TLS_CERT`/`_KEY`, `PAL_SCHEDULER_GRPC_ADDR`, `PAL_RUNTIME_MANAGER_TLS_CA`/`_CERT`/`_KEY` |
| Runtime scheduler | `PAL_GRPC_SERVICE_TOKEN`, `SCHEDULER_NODE_TOKEN`, `PAL_DEFAULT_MANAGER_ADDR`, manager TLS CA and client cert |
| Runtime manager | `PAL_GRPC_SERVICE_TOKEN`, `PAL_MANAGER_TLS_CA`/`_CERT`/`_KEY` |
| Harness | `PAL_WORKLOAD_UID`, `PAL_HARNESS_EXEC_TOKEN` |

The control plane also refuses to start in prod with `PAL_TWILIO_WEBHOOK_AUTH=off` or `PAL_USE_CLAUDE_CODE=1`, and the scheduler refuses `PAL_DIALER=stub`.

## How this list was built

`scripts/gen-env-data.mjs` greps the code on `master` for every `PAL_*` (and legacy `LANTERN_*`) read: Go `os.Getenv` and its helpers, Rust `std::env::var`, `process.env` in TypeScript, Python `os.environ`, and shell expansions in `scripts/`. Tests are excluded. That gives the name list and the "Read in" link. Defaults and meanings are written by hand in `site/src/components/docs/env-vars.json` from those reads and the startup guards (`runStartupGuards` in the control plane, `authz.rs`/`tls.rs` in the manager); the script keeps them and adds any new variable with an empty meaning, so a gap shows up as "Not documented yet" instead of going missing.

## Limits

- Every service is listed, but about a third of the rows (mostly chat-bridge tuning knobs and benchmark scripts) have no written meaning yet; the source link is the reference for those.
- Rows whose default says *set at spawn* or *from spawn.json* are written by the manager. Setting them yourself on the harness is overridden or ignored.
- Duration values are Go durations (`30s`, `1h`) unless the name ends in `_SECS`, `_MS`, `_MIN` or `_DAYS`.
- Defaults for the model-tier variables change with releases; check `services/control-plane/internal/handlers/llm_proxy.go`.
