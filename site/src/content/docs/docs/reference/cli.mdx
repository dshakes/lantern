One static Go binary, `pal`. Its source lives at `packages/cli/cmd/pal`. It boots the local stack, scaffolds and runs agents, gates CI on evals, drives sandbox VMs, and installs the data plane in your cloud.

Just looking? `pal demo` needs Docker and no API key. To build your own, `pal dev` boots the stack and `pal onboard` walks you through your first agent.

## Install

```bash
# Build from the repo
cd packages/cli && go build -o "$(go env GOPATH)/bin/pal" ./cmd/pal
pal --version
```

## demo

Starts the self-contained demo (kiosk mode): Docker only, no API key. Each visitor gets a private workspace with sample agents that is deleted after 30 minutes; answers are recorded replays from a local fixture server. Run it from inside a PAL checkout. It builds and starts Postgres, Redis, the control plane, the dashboard and the replay server as the compose project `pal-demo`, waits for `/healthz` and the demo page (up to 5 minutes), then opens `http://localhost:3001/kiosk`.

Flags: `--no-open` (don't open the browser), `--down` (stop and delete all demo data). Host ports default to 8080 and 3001; override with `KIOSK_API_PORT` and `KIOSK_WEB_PORT`. See [Demo](/docs/start/demo/).

```bash
pal demo             # start (first run builds images)
pal demo --no-open   # start without opening the browser
pal demo --down      # stop and delete all demo data
```

## onboard

First-run wizard: health check, sign-in, provider key (with a real test call), then the agentic part. It asks what you want the agent to do, the control plane designs it, you confirm, and the first run streams live. With `--yes` or a non-terminal stdin it never prompts (CI). Flags: `--provider` (`openai`|`anthropic`), `--api-key`, `--description`. See [Quickstart](/docs/start/quickstart/).

```bash
pal onboard                 # interactive
pal onboard --yes --provider anthropic --api-key "$KEY" \
  --description "Triage support tickets"   # CI
```

## doctor

Runs readiness checks against the local stack, one pass/fail line each. Exits non-zero if any hard check fails. Run it before you report a bug. The Sandbox runtime section, which never fails the run, reports whether the API uses a real scheduler or the stub, whether the scheduler and runtime manager are reachable, and whether KVM and Firecracker are present. Each failing check prints its fix.

```bash
pal doctor
```

## dev

Boots the local stack: Postgres, Redis and MinIO (Docker), the control-plane API (host Go process), the Next.js dashboard, and the WhatsApp and iMessage bridges (iMessage is skipped off macOS). Logs interleave in one terminal. Flags: `--infra-only`, `--with-whatsapp=false`, `--with-imessage=false`, `--no-open`, `--dashboard-port` (3001), `--api-port` (8080).

```bash
pal dev                # start everything
pal dev down           # stop infra containers (--volumes also deletes data)
pal dev logs           # tail all infra logs
pal dev logs postgres  # tail one service
```

## init

Scaffold a new agent directory with `agent.yaml`, `src/index.ts`, `package.json` and `tsconfig.json`. Without `--template` an interactive picker appears. Templates: `basic` (default), `research`, `tool-use`, `connector`, `personal`, `scheduled`, `approval`.

```bash
pal init my-agent
pal init my-agent --template research
```

## agents

Manage agents. Aliased as `agent`.

```bash
pal agents create --name my-agent --description "Triage tickets" [--label team=support]
pal agents list
pal agents get my-agent
pal agents delete my-agent [--force]

# Development inner loop — watches the agent dir and re-publishes on change
pal agents dev my-agent [--dir ./my-agent] [--input '{"prompt":"hi"}'] [--eval] [--yes]
```

`agents dev` is the agent development inner loop: it watches the local directory for changes to `agent.yaml` or code files, re-publishes the agent version on each change, runs a smoke input (`--input`), and streams the run events. `--eval` also runs the agent's eval suite after each publish.

## runs

Manage runs: create, list, inspect, cancel.

```bash
pal runs create --agent my-agent --input '{"topic":"AI"}' [--stream]
pal runs list [--agent my-agent] [--status succeeded]
pal runs get <run-id>
pal runs cancel <run-id> [--reason "..."]
```

## logs

Stream a run's journal events. For dev-stack containers use `pal dev logs`.

```bash
pal logs <run-id> [-f]   # journal events; -f keeps the stream open
```

## test

Run an agent's eval suite and compare against the branch baseline. Exits non-zero with a regression summary when the score drops below the baseline. Wire it into CI to gate merges. `--set-baseline` pins the run as the branch baseline. `--rehearse` replays past failed or low-score production runs instead of a suite (`--window`, default 7d). Runs execute asynchronously on the control plane, so each case waits for its run to finish; `--timeout` (default 2m) bounds that wait per case, and a failed or timed-out run scores as a failed case with its error.

```bash
pal test --agent my-agent --suite factual-accuracy
pal test --agent my-agent --suite factual-accuracy --against last-green
pal test --agent my-agent --rehearse --window 24h
```

## vm

Schedule and manage headless sandbox VMs. `pal run` takes a spec file; `vm` (aliases `vms`, `runtime`) manages what it started.

```bash
# Schedule a headless agent from a spec file
pal run agent.yaml [--input '{...}'] [--follow] [--idle-timeout 600]

# VM subcommands
pal vm list [--state running] [--limit 50]
pal vm get <vm-id>
pal vm logs <vm-id>          # SSE log stream from the harness
pal vm stop <vm-id> [--grace 30]
pal vm pause <vm-id>         # snapshot + stop, frees the quota slot
pal vm resume <vm-id>        # restore under the same vm id
pal vm fork <vm-id> --count 3   # N copies; the server caps N (100 by default, PAL_MAX_FORK_COUNT, ceiling 1000)
pal vm exec <vm-id> -- ls /tmp  # exec into a running VM (-t/-i for a PTY)
pal vm ls <vm-id> [path]     # list /workspace
pal vm cat <vm-id> <path>    # print a file (1 MiB cap)
pal vm put <vm-id> ./f.txt /workspace/f.txt   # write a file (1 MiB cap)
pal vm quota get             # current quota + today's usage
pal vm quota set --max-concurrent 10 --max-cost 50   # owner only
pal vm cluster               # node load + warm-pool capacity (owner only)
pal vm validate --kubeconfig ~/.kube/sandbox.yaml   # operator harness: gVisor/Kata isolation on a real cluster
```

`exec` talks to the runtime manager directly; point it elsewhere with `--manager-addr` (default `$PAL_MANAGER_ADDR`). `vm validate` shells `scripts/validate-cluster.sh` (run it from inside the repo; needs `kubectl`), marks legs as skipped, not failed, when a RuntimeClass is absent, and takes `--context` and `--report` too.

## deploy

Reads `agent.yaml` from the current directory, creates the agent on the control plane (or updates its system prompt and model if it already exists), saves the optional workflow graph, then calls `POST /v1/agents/{name}/deploy`. Manifest keys used: `name` (required), `description`, `model`, `system_prompt`, `labels` (set on create only; the update endpoint cannot change description or labels) and `workflow`. Other keys are ignored. Uses REST, so pass the HTTP address or let it derive one from the gRPC address.

Flags: `--json` (print the API response; same as `-o json`), `--dry-run` (one read-only lookup, reports create or update, changes nothing).

Exit codes: `0` ok, `3` unauthorized (401/403), `4` quota or budget (402), `5` not found (404), `6` server error (5xx), `1` anything else.

```text
$ cat agent.yaml
name: demo-bot
description: demo
model: auto
system_prompt: You are terse.

$ pal --api-url http://localhost:8080 deploy --json
{
  "agent": "created",
  "agentName": "demo-bot",
  "deployedAt": "...",
  "environment": "cloud",
  "id": "<agent-id>",
  "status": "live",
  "tenantId": "<tenant-id>",
  "url": "http://localhost:8080/v1/agents/demo-bot/a2a/invoke"
}
```

## hooks

Manage inbound webhook triggers: a public `POST /v1/hooks/{id}` URL bound to an agent, so GitHub, Sentry, PagerDuty or any HMAC-signing sender starts a run. Aliased as `hook` and `triggers`. See [Webhook triggers](/docs/build/triggers/).

`create` prints the signing secret once; `--secret-stdin` reads one from stdin instead (Sentry and PagerDuty generate their own). `--template` maps the payload into run input. `update` needs at least one of its flags; `--enable` / `--disable` and `--template` / `--clear-template` are mutually exclusive, and a disabled trigger answers deliveries with 404.

```bash
pal hooks create <agent> [--provider generic|github|sentry|pagerduty] [--template '{"pr":"{{payload.number}}"}'] [--secret-stdin]
pal hooks list <agent>
pal hooks get <trigger-id>
pal hooks update <trigger-id> [--enable | --disable] [--template JSON | --clear-template] [--secret-stdin]
pal hooks delete <trigger-id>
```

## infra

Generate Terraform for the data plane on AWS, GCP or Azure (EKS, GKE, AKS). Only `install` does real work: it writes the Terraform files and prints the next steps (`terraform init && plan && apply`); it does not provision anything. It needs `--tenant-id` (or `PAL_TENANT_ID`).

```bash
pal infra install --cloud aws --tenant-id "$TENANT" [--region us-east-1] [--cluster-name NAME] \
  [--existing-cluster NAME] [--instance-type TYPE] [--node-count 3] [--output-dir DIR] [--firecracker]
```

<Aside type="caution">`pal infra status`, `upgrade` and `uninstall` are placeholders. Each prints a warning that it is not wired to the backend, then the manual `kubectl`, `helm` or `terraform destroy` commands to run instead. Use [Production deployment](/docs/operate/deployment/) for the real procedure.</Aside>

## login / whoami / logout

```bash
pal login [--email --password]   # authenticate to the control plane
pal whoami                       # show current authenticated user
pal logout                       # clear stored credentials
```

## Global flags

```text
--api-url string     Control plane address (default: $PAL_API_URL or localhost:50051, gRPC)
--api-key string     API key (default: $PAL_API_KEY)
--tenant-id string   Tenant ID (default: $PAL_TENANT_ID)
-o, --output string  Output format: text or json (default text)
--rest               Use REST instead of gRPC (or set PAL_USE_REST)
```
