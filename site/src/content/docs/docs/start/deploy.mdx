<Aside type="note" title="No hosted cloud yet">
A fully managed PAL cloud is the intended offering, not a shipped one. Today you run the control plane yourself; everything below targets your own cluster.
</Aside>

## Ship an agent

From the agent's directory, against any control plane you are signed in to:

```bash
pal deploy --dry-run   # one read-only lookup: reports "create" or "update", changes nothing
pal deploy --json
```

It reads `agent.yaml` (`name`, `description`, `model`, `system_prompt`, `labels`, `workflow`), creates or updates the agent, saves the workflow graph, then calls `POST /v1/agents/{name}/deploy`. The response carries `"status": "live"` and the agent's invoke URL. Exit codes are scriptable: `3` unauthorized, `4` quota or budget (`402`), `5` not found, `6` server error.

## Put the platform in your cloud

<Tabs>
<TabItem label="Helm (one cluster)">

<Steps>

1. Supply the secrets the chart cannot create: `secrets.jwtSecret`, `credentialKey`, `receiptSecret`, `grpcServiceToken`, `schedulerNodeToken`, `appDbPassword`, plus the control plane's gRPC TLS cert and the runtime-manager mTLS client cert.

2. Install with the production values. The chart sets `PAL_ENV=production`, so every production startup guard is on and a missing secret stops the pod with its name in the log.

   ```bash
   helm install lantern ./infra/helm/lantern \
     --namespace lantern --create-namespace \
     --values infra/helm/lantern/values-prod.yaml
   ```

3. Point the CLI at it: `pal --api-url https://<your-host> login`.

</Steps>

The chart and release are still named `lantern` until the infra rename merges.

</TabItem>
<TabItem label="Terraform (data plane per cloud)">

Generate and apply a data plane for EKS, GKE or AKS. Agents then execute in that cloud while the control plane schedules them.

```bash
pal infra install --cloud aws --region us-east-1 --node-count 3 --firecracker
pal infra status
```

The data plane dials **out** to the control plane (`:50051`) with a one-time bootstrap token, so you open no inbound ports. Register it under **Settings → Data planes** or `POST /v1/data-planes`.

</TabItem>
</Tabs>
