Every builder path starts from a **checkout of the repo** and the **`pal` CLI**, a Go binary you build once. To look around without installing the CLI, `make demo` needs only Docker ([Try it: the demo](/docs/start/demo/)). To start the local stack, see [Develop locally](/docs/start/local-dev/).

## Prerequisites

| Tool | Version | Needed for | Homebrew |
| --- | --- | --- | --- |
| Docker Desktop | v4.x+ | Postgres, Redis, MinIO and the demo | `brew install --cask docker` |
| Go | 1.26+ | The `pal` CLI and the control plane on the host | `brew install go` |
| Node.js | 22+ | The dashboard and the bridges | `brew install node` |
| Git | any | Cloning | `brew install git` |
| Rust (stable) | any | Only `make build` and `make test` of the Rust services | `brew install rustup` |

<Aside>Docker must be running before you start the stack. The CLI module itself declares Go 1.25; 1.26 is what the control plane needs when you run it on the host.</Aside>

## Build the CLI

<Steps>

1. Clone the repo.

   ```bash
   git clone https://github.com/dshakes/pal.git
   cd pal
   ```

2. Build `pal` into your Go bin directory.

   ```bash
   (cd packages/cli && go build -o "$(go env GOPATH)/bin/pal" ./cmd/pal)
   ```

3. Check that it runs. If the shell says `pal: command not found`, add `$(go env GOPATH)/bin` to your `PATH`.

   ```bash
   pal --help
   ```

</Steps>

Once the stack is up (see [Develop locally](/docs/start/local-dev/)), `pal doctor` checks it and prints a fix for each failing check. `make dev-doctor` probes every service from the Makefile instead.

## Dev credentials

The local stack seeds these on first boot. They are the literal seeded values and carry the legacy name.

| Service | Value |
| --- | --- |
| PostgreSQL | `postgres://lantern:lantern@localhost:5432/lantern?sslmode=disable` |
| Redis | `redis://localhost:6379` |
| MinIO | `http://localhost:9000`, console `:9001`, `lantern` / `lanternsecret` |
| Dashboard | `admin@lantern.dev` / `lantern` at `http://localhost:3001` |
| Dev tenant | `00000000-0000-0000-0000-000000000001` (slug `dev`) |
| Dev user | `00000000-0000-0000-0000-000000000002` (role `owner`) |

<Aside type="caution">Never use these in production. Rotate every secret before a production deployment ([Production deployment](/docs/operate/deployment/)).</Aside>

## Service ports

`pal dev` runs the control plane and the dashboard. `make dev` adds the rest, except the surface-gateway, which you run yourself.

| Service | Port | Protocol |
| --- | --- | --- |
| control plane | `:8080` | REST, health, SSE |
| control plane (gRPC) | `:50051` | gRPC |
| dashboard | `:3001` | HTTP |
| workflow engine | `:50052` | gRPC |
| model router | `:50053` | gRPC |
| runtime manager | `:50054` | gRPC |
| runtime scheduler | `:50055` / `:8085` | gRPC / REST |
| gateway | `:8443` | HTTPS |
| surface gateway | `:8444` | HTTP webhooks |
| PostgreSQL, Redis | `:5432`, `:6379` | postgres, redis |
| MinIO | `:9000` / `:9001` | S3 / console |

## Make targets

| Target | What it does |
| --- | --- |
| `make dev` | The full docker-compose stack |
| `make dev-infra` | Postgres and Redis only; `pal dev --infra-only` adds MinIO |
| `make run-api` | The control plane on `:8080` |
| `make dashboard-dev` | The dashboard on `:3001` |
| `make dev-doctor` | Health-check every service |
| `make build` / `make test` / `make lint` | Compile, test, lint all languages |
| `make ci-local` | Lint, test and audit, the same matrix as CI |
| `make proto` | Regenerate from `.proto` files |
| `make clean` | Remove artifacts and docker volumes |

<Aside type="caution">Do not run `go run ./cmd/server` directly. It uses OS-user Postgres auth and fails. `make run-api` injects `DATABASE_URL`, `REDIS_URL` and `S3_ENDPOINT`.</Aside>
