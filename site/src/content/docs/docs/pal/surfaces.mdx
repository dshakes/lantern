pal reaches your messages through two small programs on your Mac, the **channel bridges**: one for **iMessage** and one for **WhatsApp**. You install them once, then run **`pal setup`**, a guided check that confirms each channel is live before it moves on. Nothing counts as connected until setup sees a real result, such as a paired WhatsApp session or an iMessage database it can read.

## Set up pal

<Steps>

1. **Install and start the bridges.** Follow [BOT-SETUP.md](repo:/blob/master/docs/personal/BOT-SETUP.md). It covers the Apple ID or WhatsApp number pal uses, Full Disk Access and Automation permission for Messages, and the bridge tokens.

2. **Start the stack and sign in.**

   ```sh
   pal dev      # starts the API, dashboard and bridges
   pal login    # setup needs a signed-in account
   ```

3. **Run the guided setup.**

   ```sh
   pal setup
   ```

   Progress is saved on the server. If you stop, running `pal setup` again resumes at the right step. The dashboard has the same flow at `/pal/onboarding`, with the same saved progress.

4. **Apply it to this Mac.** At the end, setup offers to write your answers into the bridge config. You can do it later:

   ```sh
   pal setup --apply
   ```

</Steps>

## What setup asks

| Step | What happens | If it can't continue |
| --- | --- | --- |
| 1. Meet pal | Explains what pal will read and send. You must agree before anything else. You can also opt in to learning your voice from messages you sent. | Declining changes nothing. |
| 2. Connect channels | Checks iMessage and WhatsApp live. `i` starts iMessage and checks permissions; `w` starts WhatsApp pairing (up to 3 minutes to scan the QR). One connected channel is enough. | It prints the fix for each state, for example "grant Full Disk Access to the app running the bridge". |
| 3. Learn your voice | Reads your recent 1:1 messages (never groups), shows a profile and a sample reply, and asks `[a]` sounds like me, `[r]` try again, `[s]` skip. See [Teach it your voice](/docs/pal/voice/). | Skipped if you did not opt in, or if there are too few messages. |
| 4. Set trust | Choose `auto`, `ask` or `off` for each kind of message pal recognises (bill, delivery, appointment, fraud alert, one-time code, travel, receipt, promotion), and optional quiet hours. | Holds on money and unverifiable claims stay on whatever you choose. See [Holds and trust](/docs/pal/human-in-the-loop/). |
| 5. People and facts | You describe your partner, kids, key dates and close contacts in plain words. pal proposes each fact or relationship and saves only the ones you confirm. | You can finish with none. |
| 6. First Brief | Shows your first [Brief](/docs/pal/daily/), or tells you to text `?` to yourself. | |

Setup never gives consent for you. Consent, voice approval and trust choices need a terminal; `pal setup --yes` never prompts, so it cannot get past them.

### What `--apply` writes

| File | What is written |
| --- | --- |
| `owner-profile.md` in the pal state directory (`~/.pal/`, or the path in `PAL_OWNER_PROFILE`) | The facts and relationships you confirmed, merged into `## Facts` and `## Relationships`. Other lines are kept. |
| `bridge.env` in the same directory | `PAL_QUIET_START` and `PAL_QUIET_END` if you set quiet hours; `PAL_VOICE_REASONING=1` if you approved your voice profile. |

Both files are backed up first (`.bak-<timestamp>`) and written owner-only. Restart the bridges afterwards so they pick up the change.

## The two channels

| | iMessage | WhatsApp |
| --- | --- | --- |
| Runs as | `services/imessage-bridge`, on your Mac | `services/whatsapp-bridge` (port 3100), on your Mac |
| Link | Reads `chat.db` and sends through Messages.app. Needs Full Disk Access and Automation permission. | Pairs with your own WhatsApp account by QR code (Settings, Linked devices). No Business account. |
| Also handles | RCS and newer messages. If a send fails because the contact is SMS-only, it re-delivers through the Twilio connector's `send_sms` action. | |

Both bridges take commands only from you, in a chat with yourself or from a separate bot account. See [Privacy and control](/docs/pal/privacy/).

<Aside>
The bridges run on one Mac. If it is off, nothing is processed. Both bridges run the same checks, so a reply is sent or held by the same rules on each channel.
</Aside>

Other channels (Slack, Telegram, web chat, phone) are for agents you build: see [Channels](/docs/build/channels/).
